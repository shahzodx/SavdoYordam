# Безопасность и допуск к пилоту

Реализовано: bcrypt cost 12; 256-битные случайные opaque-сессии; SHA-256 токена в БД; срок 7 дней; список и отзыв сессий, смена пароля с отзывом других сеансов; серверная проверка membership и роли; tenant-фильтры и составные FK; ограничение JSON 64 KiB; отказ от неизвестных JSON-полей; auth rate limit; query parameters; request ID; no-store; таймауты HTTP; неизменяемые финансовые журналы.

Android: INTERNET permission, backup отключён, cleartext запрещён в main manifest; исключение только для debug. Release требует HTTPS API_URL и отдельной настройки подписи; debug-ключ не используется для release. SQLite находится в private application storage, сессионный токен — secure storage. SQLite не зашифрован отдельным ключом: защита зависит от Android sandbox и устройства. Не обещаем защиту от root/разблокированного телефона.

Логи не содержат тел запросов, паролей, email, bearer-токенов и сумм. Для production нужны отдельные учётные записи БД: мигратор и API с минимальными правами; Compose сейчас использует bootstrap-пользователя и предназначен для локальной проверки. Ограничить внешний доступ к PostgreSQL, настроить TLS ingress, резервирование и контроль доступа к backup.

Открытые риски: нет восстановления забытого пароля/подтверждения email, MFA и блокировки приложения PIN/биометрией. Приглашения, экспорт и явно описанная процедура закрытия аккаунта реализованы; финансовые журналы сохраняются. Rate limit в памяти и сбрасывается при рестарте; behind-proxy нужно отдельное ingress rate limiting. До коммерческого запуска провести security review и dependency scan, определить incident response и сроки хранения.

## Юридическая проверка Узбекистана — открытые вопросы

Исходный официальный источник: [Закон «О персональных данных», LexUZ](https://www.lex.uz/ru/docs/4396428?ONDATE=27.03.2026+00), проверен 2026-11-05. Это перечень вопросов юристу, не заключение о соответствии; редакцию и дату применимости нужно повторно проверить перед пилотом.

- Определить оператора/собственника данных, правовое основание обработки и обязанности перед владельцами магазинов и покупателями.
- Проверить применимость ст. 27¹, локализацию баз, регистрацию баз, требования к трансграничной передаче и облачным обработчикам по актуальной редакции.
- Подготовить публичную политику и уведомление до сбора данных; определить согласие, обращения субъекта, доступ, исправление и удаление.
- Установить срок хранения финансовых записей и порядок удаления аккаунта с учётом обязательного хранения; ledger не удалять без правового процесса.
- Проверить обязательную фискализацию и онлайн-кассы для каждого типа торговой деятельности. SavdoYordam не сертифицированная касса и не выдаёт фискальный чек.
- До уведомлений/аналитики проверить передачу идентификаторов в FCM/Sentry; их адаптеры подготовлены, но без конфигурации отключены. См. INTEGRATIONS.md.

Не включать реальные персональные данные в тестовые дампы, issue-трекер или скриншоты исследования.
