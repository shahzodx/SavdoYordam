# Продукт и границы первой итерации

Дата: 2026-11-05. Аудитория: владелец небольшого продуктового магазина Узбекистана, который сам работает за прилавком. Первичная валюта UZS, локализации uz-Latn и ru, одна торговая точка в мобильном интерфейсе.

Основная задача: зафиксировать продажу и увидеть достоверные остатки, поступления и долги без бухгалтерских знаний. Завершённая продажа — только подтверждённая PostgreSQL-транзакция.

Три гипотезы отличия: (1) касса удобна одной рукой, (2) долг объясняется последовательностью операций, (3) потерянный ответ сервера не создаёт вторую продажу. Первые две требуют наблюдений за пользователями; третья уже проверяется тестами.

Первая итерация включает аккаунт по email/паролю, создание магазина, каталог, начальные остатки и корректировки с причиной, корзину с весовыми количествами, наличную/безналичную/частичную оплату, клиентов, погашение долга по продаже, полный возврат, расходы, агрегированные отчёты, локальный кэш и очередь повторной отправки.

MVP не включает подписки, интеграцию банка, SMS, фискальные чеки, распределённые автономные продажи, сканер, несколько филиалов в UI или автоматический расчёт налогов. Запись «карта» фиксирует уже полученную оплату, не проводит её через банк.

Пилотный критерий допуска: все критические финансовые тесты зелёные; ручной прогон на двух бюджетных Android; восстановление резервной копии; HTTPS и хранение данных согласованы; владелец понимает различие между продажей и поступлением; нет нерешённых команд после сценария обрыва связи. Эти условия пока выполнены не полностью.
