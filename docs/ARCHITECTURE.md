# Реализованная архитектура

Flutter UI → Riverpod `dataProvider` → `Repository` → Dio → Chi API → PostgreSQL. Drift/SQLite v2 хранит кэш JSON, индексированный каталог, корзину и исходящие команды с device/lease. Сессионный bearer token находится в `flutter_secure_storage`. ARB загружаются собственным `LocalizationsDelegate`; `intl` форматирует даты. go_router сохраняет пять вкладок через indexed stack.

Backend — один модульный процесс. `internal/domain` содержит независимую точную арифметику; `internal/httpapi` — обработчики identity, каталога, commerce и reporting; `internal/dbgen` — генерация sqlc (в том числе запрос сессии). Коммерческие транзакции используют явный pgx SQL рядом с бизнес-правилами; отдельного интерфейса repository ради одного PostgreSQL-адаптера нет. При росте модули commerce/identity следует вынести из HTTP-пакета без изменения контракта.

Каждая команда магазина: проверить UUID ключа → BEGIN → lock stores row → повторно проверить membership/роль → найти сохранённый результат → проверить хэш тела+пути+автора → применить доменные правила → записать ledger/audit/result → COMMIT → ответ. Пропажа ответа после COMMIT безопасна: повтор возвращает результат. При неопределённом исходе COMMIT клиент также повторяет тот же ключ.

Сериализация на магазин намеренно ограничивает throughput одной точки, зато даёт понятный порядок для остатков, долгов и возвратов. Между магазинами блокировка не общая. Нагрузочные пределы ещё не измерены. Долгих внешних вызовов внутри транзакции нет.

GET membership и все запросы данных фильтруются по store_id. Составные FK исключают cross-tenant привязку товара/клиента к продаже. PostgreSQL RLS пока не включён: изоляция опирается на серверные проверки и составные ключи; доступ к БД должен быть только у API и администраторов.

Схема инфраструктуры: Android → HTTPS reverse proxy → один API → PostgreSQL; ежедневный backup вне хоста. Redis, брокер, Kubernetes и микросервисы не нужны. FCM worker и Sentry SDK подготовлены и отключены без конфигурации. Подписки и web-dashboard остаются будущими расширениями. Добавлены закупки, приглашения, разрешение одного офлайн-устройства, частичные возвраты и аудит before/after.
