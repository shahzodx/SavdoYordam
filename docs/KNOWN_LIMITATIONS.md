# Известные ограничения пилота

Этот репозиторий — работающий первый срез, **не завершённая реализация всего master prompt**. Нельзя считать его готовым коммерческим SaaS или фискальной кассой.

- Авторизация email/password работает, но нет подтверждения email, self-service восстановления пароля, MFA и управления всеми сессиями. SMS/OTP-провайдер не подключён.
- Мобильный интерфейс выбирает первый доступный магазин; нет переключения филиалов, приглашения сотрудников или управления ролями. API проверяет owner/cashier, но UI пока не скрывает все owner-действия.
- Каталог поддерживает создание/редактирование и движение остатков. Нет категорий, фото, штрихкодов, избранного, импорта, архивации и истории отдельных изменений цены. Аудит содержит действие/автора/идентификатор, но не полный before/after snapshot.
- Нет скидок и частичных возвратов. Возврат только полной продажи; отмена завершённой продажи проводится тем же полным возвратом. Оплата «карта» не интегрирована с банком. Погашение выбирается по отдельной продаже, авансы запрещены.
- Расходы нельзя редактировать или отменять отдельной обратной операцией. Нужна модель корректировки до широкой эксплуатации. Закупки/поставщики не реализованы; себестоимость задаётся вручную, исторически фиксируется при продаже, средневзвешенная оценка запасов отсутствует.
- Отчёты содержат агрегаты сегодня/вчера/7/30 дней. API поддерживает произвольный период; в UI нет date-range picker, графиков, top-products, CSV/PDF/экспорта.
- Офлайн доступны сохранённые ответы и корзина; команды не считаются завершёнными без сервера. Нет single-device lease, резервирования остатков и автономного offline POS. Sync работает вручную и при возврате приложения; фонового worker/backoff пока нет.
- Каталог целиком кэшируется JSON и фильтруется в памяти; отдельного индексированного SQLite-каталога нет. POS использует lazy list, часть остальных экранов пока строит Column. Для большого каталога нужен performance pass.
- История клиента и движения товара в UI ограничены первой серверной страницей (100 записей); UI для последующих страниц нужен до длительного пилота. Сервер поддерживает limit/offset. Полная история продаж/клиентов/расходов загружается страницами, но без snapshot cursor при одновременных изменениях.
- Нет автоматических push/FCM, Sentry, подписок, онлайн-платежей, Next.js dashboard, экспорта и автоматизированного удаления аккаунта. Помощь и privacy-текст явно направляют к администратору пилота; публичные юридические документы ещё не подготовлены.
- SQLite не шифруется отдельно. Секреты находятся в secure storage; Android backup отключён. При недоступности/повреждении локальной БД начальная загрузка ещё требует отдельного recovery UX.
- Локальная схема только v1; upgrade migration ещё не существует и не тестировалась. Нет проверок kill-process/airplane-mode на физическом Android, TalkBack-аудита, полной accessibility-проверки всех экранов и замеров на бюджетном устройстве.
- DB isolation выполняется на уровне API и составных FK, без RLS. Compose использует bootstrap DB-user; для публичного размещения нужны отдельные роли и hardened ingress. Auth rate limiting — только в памяти одного процесса.
- Docker Compose и GitHub Actions подготовлены, но не запускались в этой среде. Production HTTPS, DNS, мониторинг, расписание backup и уведомления о сбоях не развёрнуты. Публикация приложения и платные подключения не выполнялись.

Фактический статус Android-сборки и всех запущенных проверок — в [PROGRESS.md](PROGRESS.md). Следующая работа — [ROADMAP.md](ROADMAP.md).
