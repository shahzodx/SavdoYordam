# Данные и финансовые инварианты — 0.2

Схема: Goose migrations 00001–00006 в `services/api/migrations`. sqlc читает те же миграции. PostgreSQL содержит 23 таблицы.

| Группа | Назначение |
| --- | --- |

100 tiyin = 1 UZS, количество — тысячные. Piece требует кратности 1000. Сумма команды ≤10^12 tiyin; количество ≤10^9. Строка округляется half-up. Мультипликация/распределение защищены от переполнения. Скидка владельца — целая сумма на строку, строго меньше её исходного итога; нулевые/отрицательные продажи запрещены.

Закупка увеличивает остаток и пересчитывает средневзвешенную цену в целых tiyin за единицу. При неизвестной оценке существующего ненулевого запаса себестоимость остаётся NULL. Округление цены за единицу означает, что это модель среднего учёта, а не точный FIFO по партиям. Себестоимость продажи фиксируется исторически. Возврат смешивает восстановленный запас по исторической себестоимости с текущим запасом.

Долг продажи = total − returned_total − net payments. Погашение не превышает остаток. Платёж клиента распределяется по старейшим открытым продажам одной транзакцией. Авансы запрещены.

Возврат: новые returns/return_items, положительные движения склада, снятие долга прежде денежного возврата. Сумма строки распределяется по накопленному возвращённому количеству, поэтому последовательные дробные возвраты сходятся до последнего tiyin. Денежный возврат списывает имеющуюся оплату сначала cash, затем card; деньги покупателю оператор возвращает отдельно. Отрицательные payments не могут превысить исходные поступления. Повторный возврат сверх проданного количества отклоняется.

Отчёты: Asia/Tashkent, [начало дня, начало следующего]. Sales и returns относятся к времени своей операции; подготовленная офлайн-продажа сохраняет проверенное исходное время. Received включает погашения старых долгов и вычитает refunds. Текущий долг не ограничен периодом. Расходы используют occurred_on, отмена — сегодняшнюю дату. Валовая прибыль исключает операционные расходы и становится NULL при неизвестной себестоимости относящейся к периоду строки.

Ledger/audit защищены триггерами от UPDATE/DELETE. Migration 00003 намеренно запрещает destructive down: несколько частичных возвратов нельзя безопасно свести к старому UNIQUE(sale_id). Для отката применяется проверенный backup. Миграции выполняются отдельной ролью/командой; production API требует ограниченного DB-пользователя.

Закрытие аккаунта отзывает сессии, анонимизирует профиль и контакты покупателей принадлежащих магазинов, архивирует магазины. Исторические финансовые и аудиторские записи сохраняются. Процедура показана до подтверждения; сроки и правовые основания хранения определяет оператор до публичного запуска.
